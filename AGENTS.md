# AGENTS.md — Правила разработки для AI-агента

## 1. Базовый контекст
Вся информация о бизнес-целях, стеке, пайплайне и текущих задачах находится в файле `CONTEXT.md`. **Обязательно прочитай `CONTEXT.md` перед выполнением первой задачи в сессии.**


> ⚠️ **CRITICAL GIT RULE:** Тебе КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО выполнять команды `git commit`, `git push`, `git merge` или `git rebase`. Ты можешь только изменять файлы в рабочей директории. Все коммиты делает исключительно человек.

## 2. Главное требование к коду (МАСШТАБИРУЕМОСТЬ)
Как указано в `CONTEXT.md`, главное требование заказчика — легкая взаимозаменяемость любого компонента без переписывания архитектуры:
1. **Никакого хардкода библиотек и моделей:** Всегда создавай абстрактный интерфейс (`abc.ABC` / `Protocol` в Python, `interface` в TypeScript) перед написанием конкретной реализации.
2. **Паттерн Adapter / Strategy:** Любая внешняя библиотека (например, `Silero VAD`, `WebRTC VAD`, `noisereduce`, клиент к `Whisper` или `Битрикс24`) должна быть обернута в свой класс-адаптер, реализующий общий интерфейс.
3. **Конфигурируемость:** Переключение между адаптерами должно происходить через конфиг или переменные окружения (`.env`), а не переписыванием вызовов в коде.

## 3. Технические стандарты
- **Python (для ML и аудио):** Python 3.10+, обязательна строгая типизация (`typing`, `dataclasses` или `pydantic`), логирование через `logging`, пути через `pathlib.Path`.
- **TypeScript (для Backend/Frontend):** `strict: true`, запрет на `any`, разделение на контроллеры, сервисы и адаптеры.
- **Документация и R&D:** Все исследования (Issues типа R&D) оформляются в папке `docs/` в формате Markdown с таблицами сравнения, метриками и выводами.

## 4. Алгоритм работы над задачей (Issue)
1. Прочитай `CONTEXT.md` и описание текущей задачи от пользователя.
2. Предложи краткий план файлов, которые ты собираешься создать или изменить.
3. Напиши чистый, модульный код и укажи, какой командой в терминале его нужно запустить для проверки.
