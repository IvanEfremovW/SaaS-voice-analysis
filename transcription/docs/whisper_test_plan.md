# Проверка Whisper: полнота речи, VAD и время

## Что уже известно

В [предыдущем отчёте](stt_t_one_benchmark.md) на пяти звонках (3744,7 с аудио)
первый проход Whisper занял 1174,2 с, с восстановлением — 1315,3 с.
Дополнительные 141,1 с — около 12% к времени первого прохода.
По отдельным записям доплата: 60,2 / 14,8 / 44,7 / 8,8 / 12,7 с,
то есть примерно 23,3 / 4,1 / 28,3 / 3,5 / 8,8%.
T-one greedy занял 201,2 с, но скорость и большее число слов не доказывают
лучшее качество. Проблемная фраза 5:41–6:14 первого звонка не восстановилась
ни в одном из двух режимов Whisper. Это сохранённые измерения, не новый прогон;
первый замер частично пересекался с нагрузкой демо. Нужны повторные измерения.

## Гипотеза

Под «вырезать фрагменты более 5 секунд» здесь понимается тишина, не речь.
Короткие ответы «да», «нет», суммы и возражения должны сохраняться.
Один вызов Whisper на целой записи всё равно обрабатывает её внутренними окнами;
это не единый контекст на весь звонок.

В текущем адаптере повторный проход ищет интервалы без слов от 3 секунд,
проверяет их VAD и распознаёт до 20 участков с контекстом по 4 секунды.
Он может пропускать короткие реплики, ошибки внутри уже заполненного текстом
интервала и речь, которую сам VAD не обнаружил. Настройка основного VAD через
`vad_parameters` не меняет VAD внутри восстановления: там сейчас отдельный
вызов с параметрами по умолчанию. Поэтому сначала измеряем вклад каждого этапа.

## Матрица первого этапа

Все варианты: одна модель `large-v3-turbo`, ru, INT8 на CPU, таймкоды слов,
без denoise, без внешнего VAD, без промпта и без контекста предыдущего текста.
Температурный fallback остаётся штатным и одинаковым для всех вариантов.

| Вариант | Изменение | Проверяем |
|---|---|---|
| current_recovery | Встроенный VAD + текущее восстановление | Польза и стоимость повторов |
| vad_default | Встроенный VAD, без восстановления | Контроль одного прохода |
| full_audio | Без VAD и восстановления | Не выбрасывает ли VAD речь |
| vad_5s | Пауза 5000 мс, padding 400 мс, threshold 0.5 | Сохранение контекста между репликами |
| vad_5s_sensitive | Как vad_5s, threshold 0.35 | Тихая речь против шума/галлюцинаций |
| vad_5s_beam1 | Как vad_5s, beam_size=1 вместо 5 | Компромисс скорости и ошибок |

`min_silence_duration_ms=5000` — минимальная внутренняя пауза для разделения
речевых интервалов. Начальная/конечная тишина тоже может обрезаться; это не
строгое правило «удалять только любую тишину >5 с». VAD определяет отсутствие
речи, а не нулевую амплитуду. Шум и музыка также могут быть удалены.
Faster-whisper восстанавливает таймкоды после встроенного VAD на шкалу входа.

## Запуск из корня репозитория

Использовать существующее окружение `.venv` с зависимостями STT. При необходимости:
`.venv/bin/python -m pip install -r stt/requirements.txt`.
Остановить обработку в демо и другие тяжёлые задачи, подключить питание.
Каждый запуск требует нового выходного каталога: старые результаты не перезаписываются.
Модель может скачаться при первом запуске. Аудио обрабатывается локально.

Сначала один полный звонок: выбранный первым файл `4425aca0…` содержит известные проблемы.
Перед измерениями будет ещё один полный прогревочный проход; он не входит в таблицу времени.

```bash
.venv/bin/python -m stt.benchmark --limit 1 --output output/whisper-pilot
.venv/bin/python -m stt.benchmark_report output/whisper-pilot
```

Затем все пять звонков, три повтора. Это длительный прогон: первый этап на
одном файле позволит оценить время. Нагрузка последовательная, модель одна.

```bash
.venv/bin/python -m stt.benchmark --repeats 3 --output output/whisper-matrix
.venv/bin/python -m stt.benchmark_report output/whisper-matrix
```

Можно ограничиться выбранными вариантами:

```bash
.venv/bin/python -m stt.benchmark --variants vad_default vad_5s full_audio --output output/whisper-short
```

Вход задаётся через `--input`: файл или каталог (поиск рекурсивный).
`--config` позволяет передать другую JSON-матрицу без правки кода.
`--model`, `--device`, `--compute-type` меняют модель и вычисления.
Манифест фиксирует реальные device/compute type, версии библиотек, SHA256 аудио,
git HEAD и состояние рабочей директории. Весам по имени соответствует локальный
кэш на момент запуска; для строгой повторяемости передать фиксированный локальный
каталог модели в `--model`. Не менять зависимости/веса между сравнениями.

## Как оценивать

1. Сначала прослушать 0:55–1:25, 1:53–2:06, 5:41–6:14 на `4425aca0…`,
   сверить тексты `.txt` рядом с JSON. Отдельно отметить пропуски, выдуманные слова,
   неверные суммы/имена, дубли, короткие ответы и сдвиг таймкодов.
2. Добавить тихую речь, перебивания, музыку, длинные паузы, начало/конец записи
   и несколько обычных участков. Проверять одинаковые места у всех вариантов.
   Согласие с T-one использовать как подсказку для прослушивания, не как эталон.
3. Для автоматического WER нужны полные ручные расшифровки звонков в
   `samples/references/<имя MP3 без расширения>.txt`. Не класть туда отдельную
   фразу вместо полного эталона. Отсутствующий или пустой эталон даёт пустой WER.
4. Сравнить по каждому звонку медиану времени из трёх повторов, разброс и ошибки.
   RTF = время обработки / длительность исходного аудио (меньше лучше).
   Замер включает чтение файла, VAD, декодирование и повторы, но исключает
   загрузку модели, прогрев и запись отчётов. Первый проход отдельно не вычитается:
   варианты `current_recovery` и `vad_default` измеряются независимо.
5. Выбирать самый быстрый вариант, сохраняющий важные реплики и качество по
   ручному эталону. Зафиксировать допустимое ухудшение WER заранее; например,
   не более 1 процентного пункта при отсутствии новых пропусков важных реплик.
   Пять звонков дают пилотную оценку, затем нужна проверка на новых записях.

```bash
.venv/bin/python -m stt.benchmark_report output/whisper-matrix --references samples/references
```

Сводка создаёт `report.md`, `metrics.csv`, тексты с таймкодами. WER нормализует
регистр, пунктуацию и ё/е, но не числа словами/цифрами. Количество слов само по
себе не метрика качества. При ошибках запуск возвращает ненулевой код, уже
полученные результаты остаются; сводка отмечает ошибки. Неполные наборы нельзя
сравнивать по общей медиане RTF без проверки таблицы по файлам.

Для последующего разбора достаточно сообщить путь к каталогу результатов.
Он находится в игнорируемом `output/`; тексты звонков не следует коммитить.

## Второй этап и решение для сервиса

После выбора VAD отдельно сравнить `small`, `medium`, `large-v3-turbo`, `large-v3`
на той же матрице из одного-двух лучших вариантов. Потом — beam 1/5,
`condition_on_previous_text`, короткий словарь терминов в `initial_prompt`,
отдельно denoise включён/выключен. Не менять всё одновременно.
Если запись стерео с раздельными собеседниками, проверить распознавание каналов
отдельно: моно-сведение может ухудшать разбор перебиваний. Это отдельный эксперимент.

Для этого сервиса разумная отправная точка: постоянно загруженная модель в
воркере, очередь с ограничением параллелизма, один основной проход, консервативный
VAD с сохранением контекста, исходная временная шкала. Повторять только доказанно
проблемные участки и ограничивать бюджет повторов; оценивать эффект на эталоне.
Автоматическое восстановление всех пробелов не гарантирует полноту.

Для GPU отдельно проверить FP16/INT8_FLOAT16 и batched inference, измеряя VRAM,
пропускную способность и задержку очереди. BatchedInferencePipeline — отдельный
режим со своими настройками VAD, его нельзя считать просто ускоренной копией
текущего прохода. В этот первый CPU-бенчмарк он намеренно не включён.

Это предлагаемый дизайн для проекта, а не утверждение, что все production-системы
используют одну схему. Основания: [faster-whisper: VAD, batching и benchmarks](https://github.com/SYSTRAN/faster-whisper),
[параметры VAD](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/vad.py),
[Whisper: внутренние окна](https://github.com/openai/whisper#python-usage).
