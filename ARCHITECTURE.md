# Архитектура SaaS Voice Analysis

[Контекст проекта](CONTEXT.md) описывает бизнес-цели, скоуп и требования заказчика.

## Реализованный конвейер

Оркестратор загружает запись через адаптер, при необходимости передаёт её в предобработку и запускает STT. Предобработка конвертирует аудио, подавляет шум и использует VAD для выделения речи. STT возвращает текст и интервалы на шкале полученного аудио. Оркестратор восстанавливает шкалу исходного звонка по интервалам VAD. Предобработка и STT доступны через Python и HTTP.

## Целевая система

Битрикс24 → загрузчик записей → очередь → Python-воркер предобработки и STT → оценка через Qwen → Node.js API и PostgreSQL → React-интерфейс. Интеграция с CRM, очередь, оценка и кабинет относятся к целевому конвейеру, описанному в контексте проекта.

## Границы HTTP-сервисов

Общий [audio_http.py](audio_http.py) ограничивает POST-запросы размером 32 МиБ и двумя одновременными запросами на процесс. Перед запуском обработки адаптер PyAV проверяет фактический поток без накопления всего аудио в памяти. Лимиты составляют 30 минут и 64 млн отсчётов суммарно по каналам.

Маршруты обработки по серверному пути включаются только при заданных `AUDIO_SHARED_ROOT` и `AUDIO_SHARED_TOKEN`. Клиент передаёт Bearer-токен, а пути проверяются относительно выделенного каталога. Каталог предназначен для доверенных процессов. Готовый WAV публикуется атомарно без перезаписи существующего файла.

Прямые вызовы Python-интерфейсов рассчитаны на доверенный код. HTTP-ограничения применяются при входе в сервис.
